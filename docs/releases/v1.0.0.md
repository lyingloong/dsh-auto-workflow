# dsh-auto-workflow v1.0.0

这是 **dsh-auto-workflow**的首个公开发布。包名、GitHub Release 和 tag 均为 `dsh-auto-workflow` / **v1.0.0**，仓库为 [lyingloong/dsh-auto-workflow](https://github.com/lyingloong/dsh-auto-workflow)。

## 本次提供什么

- **持久化并发节点图**：agent、command、HTTP、Human、fan-out/join、gate 与 subworkflow；独立 packet、根/节点并发和引用式状态存储。
- **常驻调度与人工门禁并存**：Host 运行期间，idle 或单项 Human 等待不阻塞其他工作；新的 packet 可随时进入。Auto 不代表跳过授权或审批。
- **七个工具与会话看板**：定义、创建、运行、入队、逐项决策、控制和只读状态；节点容量、队列、Human 待办、模型候选和按需产物读取。
- **唯一主业务示例**：GitHub 项目的本地 clone 持续开发。已有 seed / 显式用户 intake → 用户 priority 0 与稳定 ID → 每需求 retained detached worktree → 3 engineer + 3 reviewer 池（每需求一位 reviewer，root 6）→ Human merge 门禁 → 串行本地集成 → 默认 retain。
- **审查与恢复约束**：revision / `engineeringEpoch` 绑定、不可变实现与 review、typed `busy`、显式 snapshot reconciliation、冲突现场保留、ignored 数据保护与受限清理。
- **源码布局**：当前引擎位于 `src/`，不再保留历史版本化目录；公开入口、看板和运行数据格式不受目录整理影响。

## 固定版本安装

需要 Node.js 22.5+、DeepSeek Harness 0.2.1-rc.5+；首发已验证的 DSH 版本为 0.2.1-rc.5。将 `desktop` 换成实际 profile：

```bash
dsh plugin --profile desktop add github:lyingloong/dsh-auto-workflow#v1.0.0
```

也可从 [本 Release](https://github.com/lyingloong/dsh-auto-workflow/releases/tag/v1.0.0) 下载打包资产，再本地安装：

```bash
dsh plugin --profile desktop add /absolute/path/dsh-auto-workflow-1.0.0.tgz
```

安装后重启 DSH Host 并刷新 Web GUI。安装不会复制业务示例到目标仓库、授权命令或自动启动 run；按 [快速入门](https://github.com/lyingloong/dsh-auto-workflow/blob/v1.0.0/README.md) 和 [开发示例指南](https://github.com/lyingloong/dsh-auto-workflow/blob/v1.0.0/docs/examples/development/README.md) 准备项目。

## 验证范围

公开 [验证说明](https://github.com/lyingloong/dsh-auto-workflow/blob/v1.0.0/docs/verification.md) 集中记录最终发布前回归结果与真实模型/Git 执行概况，不在多处固化易变测试数。覆盖包括：并发 packet、Human 隔离、权限与执行所有权、有序模型回退、看板与 API、实际本地 Git worktree、同时 3+3 工作池、Human 返修、精确产物批准、保留策略及异常恢复。

回归与隔离的真实执行不等于任意项目的无人值守保证，也不证明多 Host、外部审批服务或掉电事务。

## 明确边界

- command/HTTP 权限默认 deny，先获得用户批准；agent 工具权限独立管理。
- Host 停止、插件重载、执行失败或中断后保留证据，**不自动重放**不确定副作用。状态引用落盘不等于 Git/HTTP exactly-once、自动 rollback 或掉电耐久性承诺。
- 示例只消费已有 seed 和显式 intake，不监听全部聊天，不自动抓 GitHub Issues。
- 无自动远端 push、PR、merge 或部署。需要发布时，可在单个共享集成批次分支完成后另行显式授权并手动操作；不默认直接 push 受保护的 `main`，也不为每需求创建分支。
- 合并后默认保留 detached worktree；清理是单独授权/策略约束的行为，不是合并的隐含副作用。
