# dsh-auto-workflow v1.2.0

这是 `dsh-auto-workflow` 的 minor release，重点是 DSH 0.2.2 兼容与开发示例的 seed 生命周期。

## 兼容性边界

- **需要 DeepSeek Harness 0.2.2-rc.2+**：宿主在 0.2.2-rc.2 把 `SubagentActivationSpec` 的任务字段移到顶层并移除嵌套 `request`；0.2.2-rc.1 及更早只认旧形状。`engines.dsh` 已提升为 `>=0.2.2-rc.2`，本机在 0.2.2-rc.5 验证。
- **示例业务 store 升到 `version: 3`**：版本 2 的 dataRoot 会被拒绝，不迁移、不删除；需要新的 dataRoot，旧库保留供检查。

## 修复

- agent 节点在 DSH 0.2.2-rc.2+ 上无法启动（`all model candidates failed: … Cannot read properties of undefined (reading 'id')`），现在按顶层 spec 启动；新增 `tests/host-contract.test.mjs` 锁定宿主契约与 `engines.dsh` 下限。
- `runner.updateModels` 不再把「刚收尾且没有剩余工作」的调度切片当成忙碌：run 刚 park 时从看板改模型不再偶发 409；真正有 running/ready 工作时仍立即拒绝。

## 示例（GitHub 持续开发工作流）

- seed 轮转：状态收敛为 `queued` / `mining` / `proposed` / `retired`，按 `rotationRound` 轮转而不是时间冷却；`proposal:null` 与需求 `merged`/`rejected` 都会让 seed 重新入队。
- 同一方向的重复产出使用 `req-<seed>-r<n>` 后缀，不覆盖已终止的需求。
- `queue-check` 的 backlog 计入正在 mining 的 seed；`headroom` 同时受水位与 `maxMiningSeeds` 限制，`seed-batch` 只领剩余余额。
- 新增 `recover-seeds` / `retire-seed` / `rearm-seed`：中断留下的过期 claim 由操作者显式释放，运行时不自动回收。
- `pr-init` 新增 `manualGate`：branch protection、conversation resolution 与 required checks 降为警告；`gh` 认证、仓库访问、允许 merge commit、merge-ready 标签与 PR template 仍是硬性要求。

## 升级

1. 安装 v1.2.0 并重启 Host。
2. 确认 DSH 为 **0.2.2-rc.2 或更新**；更早版本无法启动 agent 节点。
3. 开发示例脚本是 materialize 到业务仓库的副本：重新复制本版本脚本。
4. 示例业务数据需要新的 dataRoot（store `version: 3`）；旧库原样保留。
5. 之前为绕过 #23 手动改过部署副本的，重新安装后不再需要该补丁。
